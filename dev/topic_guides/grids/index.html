Creating a grid

In Ferrite a grid is generated by meshing a domain. In IGA the domain is the geometry: a spline patch that already describes the exact shape. An IGAGrid therefore does not create anything geometric — it wraps a G+Smo geometry and presents it to Ferrite as an AbstractGrid.

From a geometry to a grid

Geometries come from TinyGismo.jl, which is re-exported by FerriteGismo. The factory functions cover the common shapes:

using FerriteGismogeometry = createBSplineSquare(1.0)     # unit squaregrid = IGAGrid{2}(geometry)getncells(grid), getnnodes(grid)
(1, 4)

The type parameter is the spatial dimension. If the parametric dimension differs from it — a curve or a surface in 3D — give both: IGAGrid{3, 1}(curve) is a spline curve embedded in three-dimensional space.

Two words change meaning compared to a Ferrite Grid:

FerriteIGAGrid
cellone non-empty knot span (Bézier element)
nodeone spline control point

A cell stores the indices of the basis functions that are active on its knot span, which is what makes CellIterator, celldofs and reinit! work unchanged. Control points are generally not points on the geometry, which matters for boundary conditions (see Boundary conditions).

Building your own patch

Any spline geometry works. A patch is a basis plus its control points, given row-wise and ordered lexicographically with the first parametric direction running fastest:

kv = KnotVector([0.0, 0.0, 1.0, 1.0])          # linear, one elementcontrolPoints = [    0.0 0.0        # ξ = (0, 0)    4.0 0.0        # ξ = (1, 0)    0.0 1.0        # ξ = (0, 1)    4.0 0.5        # ξ = (1, 1)]tapered = TensorBSpline{2}(TensorBSplineBasis{2}(kv, kv), controlPoints)

This bilinear patch is a tapered strip, and the taper is described exactly — refinement never changes the geometry, only the space of functions on it.

Refinement

Refine the geometry before constructing the grid; the grid caches the knot spans and the active basis functions of the geometry it was built from.

degreeElevate!(tapered, 1)          # p-refinement: degree 1 -> 2 in both directionsuniformRefine!(tapered, 2)          # h-refinement: halve every knot span twiceinsertKnot!(tapered, 0.9, 1)        # a single knot in parametric direction 1grid = IGAGrid{2}(tapered)numElements(grid)                   # elements per parametric direction
(4, 3)

uniformRefine! doubles the number of elements per call. For a specific element count, or for a graded mesh, insert the knots yourself with insertKnot!/insertKnots! — the direction argument is 1 or 2 (0 means all directions for degreeElevate!).

Elevating the degree first and refining afterwards keeps the continuity high: an interior knot of multiplicity one gives $C^{p-1}$ continuity across the element boundary, which is where the smoothness advantage of IGA comes from.

Parameter space and physical space

Everything an IGAGrid is asked about happens in one of two spaces, and mixing them up is the most common source of confusion:

FerriteGismo.toPhysical(grid, [1.0, 1.0])   # parametric corner -> physical point
2-element Vec{2, Float64}:
 4.0
 0.5
  • Parameter space is the unit square spanned by the knot vectors. Facet sets, boundary sides (:left, :right, :bottom, :top) and evaluation points are given here.
  • Physical space is where the control points and the quadrature points live. Values reported by spatial_coordinate, getcoordinates and the coordinates passed to load or boundary-condition functions are physical.

parameterSpaceGrid builds a plain Ferrite grid of the knot spans; it is what the VTK export and the evaluation at grid nodes use internally.

Boundary facet sets

Facet sets are not stored but computed on demand from the knot spans, so no addfacetset! is needed. The four (2D) sides of the parametric domain are available by name:

facets = getfacetset(grid, "right")length(facets)
3

These sets are ordinary OrderedSet{FacetIndex}s and work with FacetIterator and FacetValues as usual — see Applying forces.

Local refinement

uniformRefine! and insertKnot! act on the whole patch: a knot inserted in one direction splits every element along it. Refining only a corner needs a hierarchical basis, which adds finer levels over just the regions that need them:

patch = THBSpline{2}(createBSplineSquare(1.0))refineElements!(patch, RefinementBox(2, 1:1, 1:1))   # the first coarse cell onlyhierGrid = IGAGrid{2}(patch)getncells(hierGrid), isHierarchical(hierGrid)
(4, true)

Such a grid needs one SubDofHandler per group of elements sharing an active-function count, since that count is no longer constant — see Hierarchical splines.

One patch at a time

An IGAGrid describes a single patch. Multi-patch geometries, and hence internal interfaces, are not supported yet.

getfacetset(grid::IGAGrid, name::String)

Return the set of boundary facets (as Ferrite.FacetIndex entries) of grid on the parametric boundary name.

IGAGrid{sdim}(geometry::gsGeometry) IGAGrid{sdim, rdim}(geometry::gsGeometry)

An Isogeometric Analysis (IGA) grid backed by a G+Smo geometry, implementing the Ferrite.AbstractGrid interface.

isHierarchical(grid::IGAGrid) -> Bool

Whether grid is backed by a hierarchical (HB/THB) basis rather than a tensor-product one.

numElements(grid::IGAGrid)

Return a tuple with the number of elements of grid per parametric direction, e.g. (nx, ny) for a two-dimensional grid.
