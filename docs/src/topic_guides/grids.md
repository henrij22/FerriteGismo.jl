# Creating a grid

In Ferrite a grid is generated by meshing a domain. In IGA the domain *is* the geometry: a
spline patch that already describes the exact shape. An [`IGAGrid`](@ref) therefore does not
create anything geometric — it wraps a G+Smo geometry and presents it to Ferrite as an
`AbstractGrid`.

## From a geometry to a grid

Geometries come from [TinyGismo.jl](https://github.com/henrij22/TinyGismo.jl), which is
re-exported by FerriteGismo. The factory functions cover the common shapes:

```@example grids
using FerriteGismo

geometry = createBSplineSquare(1.0)     # unit square
grid = IGAGrid{2}(geometry)
getncells(grid), getnnodes(grid)
```

The type parameter is the spatial dimension. If the parametric dimension differs from it —
a curve or a surface in 3D — give both: `IGAGrid{3, 1}(curve)` is a spline curve embedded in
three-dimensional space.

Two words change meaning compared to a Ferrite `Grid`:

| Ferrite | `IGAGrid` |
|:--------|:----------|
| cell    | one non-empty knot span (Bézier element) |
| node    | one spline control point |

A cell stores the indices of the basis functions that are *active* on its knot span, which
is what makes `CellIterator`, `celldofs` and `reinit!` work unchanged. Control points are
generally **not** points on the geometry, which matters for boundary conditions (see
[Boundary conditions](boundary_conditions.md)).

## Building your own patch

Any spline geometry works. A patch is a basis plus its control points, given row-wise and
ordered lexicographically with the first parametric direction running fastest:

```@example grids
kv = KnotVector([0.0, 0.0, 1.0, 1.0])          # linear, one element
controlPoints = [
    0.0 0.0        # ξ = (0, 0)
    4.0 0.0        # ξ = (1, 0)
    0.0 1.0        # ξ = (0, 1)
    4.0 0.5        # ξ = (1, 1)
]
tapered = TensorBSpline{2}(TensorBSplineBasis{2}(kv, kv), controlPoints)
nothing # hide
```

This bilinear patch is a tapered strip, and the taper is described *exactly* — refinement
never changes the geometry, only the space of functions on it.

## Refinement

Refine the geometry **before** constructing the grid; the grid caches the knot spans and the
active basis functions of the geometry it was built from.

```@example grids
degreeElevate!(tapered, 1)          # p-refinement: degree 1 -> 2 in both directions
uniformRefine!(tapered, 2)          # h-refinement: halve every knot span twice
insertKnot!(tapered, 0.9, 1)        # a single knot in parametric direction 1

grid = IGAGrid{2}(tapered)
numElements(grid)                   # elements per parametric direction
```

`uniformRefine!` doubles the number of elements per call. For a specific element count, or
for a graded mesh, insert the knots yourself with `insertKnot!`/`insertKnots!` — the
direction argument is `1` or `2` (`0` means all directions for `degreeElevate!`).

Elevating the degree first and refining afterwards keeps the continuity high: an interior
knot of multiplicity one gives ``C^{p-1}`` continuity across the element boundary, which is
where the smoothness advantage of IGA comes from.

## Parameter space and physical space

Everything an `IGAGrid` is asked about happens in one of two spaces, and mixing them up is
the most common source of confusion:

```@example grids
FerriteGismo.toPhysical(grid, [1.0, 1.0])   # parametric corner -> physical point
```

- **Parameter space** is the unit square spanned by the knot vectors. Facet sets, boundary
  sides (`:left`, `:right`, `:bottom`, `:top`) and evaluation points are given here.
- **Physical space** is where the control points and the quadrature points live. Values
  reported by `spatial_coordinate`, `getcoordinates` and the coordinates passed to load or
  boundary-condition functions are physical.

[`parameterSpaceGrid`](@ref) builds a plain Ferrite grid of the knot spans; it is what the
VTK export and the evaluation at grid nodes use internally.

## Boundary facet sets

Facet sets are not stored but computed on demand from the knot spans, so no
`addfacetset!` is needed. The four (2D) sides of the parametric domain are available by
name:

```@example grids
facets = getfacetset(grid, "right")
length(facets)
```

These sets are ordinary `OrderedSet{FacetIndex}`s and work with `FacetIterator` and
`FacetValues` as usual — see [Applying forces](forces.md).

!!! note "One patch at a time"
    An `IGAGrid` describes a single patch. Multi-patch geometries, and hence internal
    interfaces, are not supported yet.
